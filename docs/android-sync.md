# Android · 폴더블 · 개인 데이터 동기화

## 설치와 첫 동기화

1. `build/app/outputs/flutter-apk/app-debug.apk`를 Android 휴대폰에 설치합니다.
   현재 빌드는 직접 설치하는 개발용 APK이며 Play Store 배포용 서명은 포함하지 않습니다.
2. 휴대폰의 저장소는 앱 전용 폴더에 자동으로 생성됩니다. 폴더 접근 권한을
   추가로 허용할 필요가 없습니다. PC에서는 기존 Vault 폴더를 그대로 사용합니다.
3. 구름 아이콘 → **계정 및 동기화**에서 개인 서버에 등록된 이메일과 비밀번호로
   로그인합니다. 최초 계정 정보는 운영 PC의 `.migration/app-account.json`에 있습니다.
   Supabase 계정이나 Coolify 관리자 비밀번호를 사용하지 않습니다.
4. PC에서 **저장하고 동기화**를 누르면 편집 중인 문서를 저장하고 서버와 맞춥니다.
5. 휴대폰에서도 같은 계정으로 로그인하고 **저장하고 동기화**를 누릅니다.
   앱의 동기화 상태에서 마지막 완료 시각을 확인합니다.

서버 주소: `https://scrapnote.134.185.114.149.sslip.io`.
Supabase에 남은 데이터는 가져오지 않았으며 운영 PC의 로컬 Vault를 기준으로 이전했습니다.
기존 모바일 Vault가 Supabase에 연결되어 있으면 원래 `vault`를 보존하고
별도 `vault-oracle` 폴더에 새 서버 데이터를 받습니다. 휴대폰에만 있던 과거 편집은
자동 병합하지 않습니다. PC는 검증된 기존 Vault를 그대로 사용합니다.

로그아웃해도 기기의 파일은 남습니다. 앱을 삭제하면 앱 전용 로컬 파일도
삭제되므로, 다시 설치할 때는 마지막으로 서버에 동기화한 데이터가 복원됩니다.
로그인 세션은 30일 뒤 만료되며 다시 로그인하면 됩니다. 공개 회원가입과
인증 메일 발송은 사용하지 않습니다.

## 화면과 입력

- 600px 미만: 라벨이 있는 하단 탐색. 키보드가 열리면 편집 공간을 확보합니다.
- 편집 영역 700px 미만: 목록/편집 전환. 목록은 숨겨진 뒤에도 다시 열 수 있습니다.
- 넓은 화면: 목록과 편집기를 나란히 표시합니다. Android에서는 넓이와 관계없이
  새 문서·이미지 첨부·저장에 48px 터치 영역을 제공합니다.
- 펼쳐진 폴더블은 사용 가능한 넓이에 따라 배치가 바뀝니다. 화면을 가리는
  힌지나 반쯤 접힌 경계가 있으면 상단/시작 쪽의 가려지지 않는 영역을 사용합니다.
  접힘 경계 양쪽에 서로 다른 화면을 배치하는 방식은 아닙니다.
- 휴대폰 가계부는 세로 목록과 스크롤 가능한 입력 폼을 사용합니다.
- `Where`에는 전체 과거 지출에서 최대 8개 장소를 제안합니다. 대소문자와 양끝
  공백을 무시해 중복을 합치고 최근 날짜의 표기를 사용합니다. 앞부분 일치가
  먼저 나오고 부분 일치가 이어집니다. 새 장소도 자유롭게 입력할 수 있습니다.
  터치·방향키·Enter로 선택해도 지출 자체가 자동 저장되지는 않습니다.

## 저장·충돌·오프라인

- 편집 중인 내용은 로컬 복구 초안으로 보관합니다. 서버에는 저장된 파일만
  동기화하며, 수동 동기화는 편집 내용을 먼저 저장합니다.
- 같은 파일을 두 기기에서 다르게 수정하거나 수정과 삭제가 겹치면 동기화를
  멈춥니다. 계정 화면에서 파일별로 **이 기기** 또는 **서버** 버전을 선택합니다.
- 교체/삭제되는 로컬 파일은 `.trash/sync/`에 사본을 보관합니다. 복구 초안,
  휴지통, 동기화 상태 파일은 서버로 보내지 않습니다.
- 로그인 세션은 Android Keystore 또는 macOS 로그인 Keychain에 보관합니다.
- 저장소 하나는 하나의 서버/계정에 연결됩니다. 다른 계정으로 같은 로컬
  저장소를 업로드하려 하면 차단합니다. 계정별로 별도 저장소를 사용해야 합니다.
- 파일당 동기화 한도는 25 MiB입니다. 실패하면 로컬 내용을 보존하고 재시도합니다.
- 8 MiB를 넘는 일반 사진은 Vault에 저장할 때 긴 변 최대 4096 px로 줄이고
  압축합니다. HEIC/HEIF는 기기에서 읽을 수 있으면 JPEG로 변환합니다.
  원본 파일은 변경하지 않습니다. 투명한 PNG는 투명도를 유지합니다.
  이전에 저장된 25 MiB 초과 사진은 다음 수동 동기화 때 문서의 이미지 링크까지
  교체하며, 이전 파일과 Markdown을 `.trash/image-optimization/`에 보관합니다.
  기기에서 HEIC/HEIF를 읽지 못하거나 압축할 수 없는 형식은 이유를 표시하고
  원본을 그대로 둡니다.
- 앱 종료 상태의 백그라운드 동기화와 문장 단위 실시간 공동 편집은 지원하지 않습니다.

## 서버 구성과 검증

Flutter 앱은 HTTPS Scrapnote API만 호출합니다. PostgreSQL에는 사용자·해시된 세션,
파일 목록과 버전, Markdown·JSON 원본을 저장합니다. 사진은 전용 Zipline 계정에
비밀번호 보호 상태로 보관하고 API가 인증 후 원본을 중계합니다. Zipline 토큰과
사진 비밀번호 생성 키는 앱에 포함하지 않습니다.

동기화는 SHA-256으로 원본을 확인하고, 기대 버전이 맞을 때만 목록을 커밋합니다.
인증 없는 접근, 다른 사용자 데이터 접근, 누락된 파일을 참조한 커밋, 오래된 버전의
커밋을 거절합니다. 실제 PostgreSQL에서 동시 커밋과 롤백도 검증했습니다.
상세 배포·복구 절차는 [서버 안내](../server/README.md)를 참고하세요.

다른 서버로 빌드할 때에는 다음 값을 지정합니다. 기존 Vault의 서버/계정 연결은
주소만 바꿔 강제로 덮어쓸 수 없으며 별도 검증/이전이 필요합니다.

```sh
flutter run --dart-define=SCRAPNOTE_API_URL=https://YOUR_API_DOMAIN
```

물리 Android/폴더블 기기에서의 실제 접기·펼치기와 개인 계정 로그인 후 양방향
전송은 별도 기기 확인이 필요합니다. 로컬 이전 도구는 서버 파일을 전부 다시
내려받아 해시를 비교한 다음에만 PC의 동기화 연결을 전환합니다.
