# Android · 폴더블 · 개인 데이터 동기화

## 설치와 첫 동기화

1. `build/app/outputs/flutter-apk/app-debug.apk`를 Android 휴대폰에 설치합니다.
   현재 빌드는 직접 설치하는 개발용 APK이며 Play Store 배포용 서명은 포함하지 않습니다.
2. 휴대폰의 저장소는 앱 전용 폴더에 자동으로 생성됩니다. 폴더 접근 권한을
   추가로 허용할 필요가 없습니다. PC에서는 기존 Vault 폴더를 그대로 사용합니다.
3. PC 앱의 구름 아이콘 → **계정 및 동기화**에서 계정을 만들고 이메일을 확인한
   뒤 로그인합니다. 확인 링크는 가입을 시작한 기기에서 열면 Scrapnote로 돌아옵니다.
   다른 기기에서 확인했거나 자동 로그인이 되지 않으면 가입한 비밀번호로 로그인합니다.
   이 계정은 Supabase 대시보드 운영 계정과 별개입니다.
4. **저장하고 동기화**를 누르면 저장되지 않은 문서를 먼저 저장한 후,
   PC의 노트·스크랩·이미지·가계부·가계부 표시 설정을 개인 서버에 연결합니다.
5. 휴대폰에서도 같은 계정으로 로그인하고 **저장하고 동기화**를 누릅니다.
   이후 저장한 변경은 자동으로 전송되며, 다른 기기의 변경은 앱 복귀 또는
   전경 실행 중 최대 약 1분 주기의 확인으로 반영됩니다.

서버 주소: `https://bgprybazlurcalbdinml.supabase.co` (서울 리전).
로그아웃해도 기기의 파일은 남습니다. 앱을 삭제하면 앱 전용 로컬 파일도
삭제되므로, 다시 설치할 때는 마지막으로 서버에 동기화한 데이터가 복원됩니다.

### 인증 메일을 열었는데 오류가 보이는 경우

- 이미 사용한 링크를 다시 누르면 `otp_expired`가 표시될 수 있습니다. 먼저
  앱에서 비밀번호로 로그인합니다. 인증 완료된 계정은 다시 가입할 필요가 없습니다.
- 아직 인증되지 않았다면 이메일을 입력하고 **인증 메일 다시 받기**를 누릅니다.
  재발송 후에는 가장 최근 메일을 사용합니다. 연속 발송은 60초간 제한됩니다.
- 프로젝트의 Site URL과 허용 Redirect URL은
  `com.scrapnote.app://auth-callback`입니다. Android·macOS·iOS에 앱 링크를
  등록했고, Supabase SDK가 인증 결과를 받아 계정 화면을 갱신합니다.
  Windows와 웹의 콜백 주소/설치 등록은 별도 구성 대상입니다.
- 기존 메일에 들어 있는 `localhost:3000` 주소는 소급 변경되지 않습니다.
  새 빌드와 새 인증 메일을 사용하세요.
- 현재 무료 기본 발송 서비스의 템플릿 편집에는 별도 SMTP 또는 유료 플랜이
  필요합니다. 이 프로젝트는 기본 확인 링크를 사용하며 숫자 코드 방식은 적용하지 않았습니다.

## 화면과 입력

- 600px 미만: 라벨이 있는 하단 탐색. 키보드가 열리면 편집 공간을 확보합니다.
- 편집 영역 700px 미만: 목록/편집 전환. 목록은 숨겨진 뒤에도 다시 열 수 있습니다.
- 넓은 화면: 목록과 편집기를 나란히 표시합니다. Android에서는 넓이와 관계없이
  새 문서·이미지 첨부·저장에 48px 터치 영역을 제공합니다.
- 펼쳐진 폴더블은 사용 가능한 넓이에 따라 배치가 바뀝니다. 화면을 가리는
  힌지나 반쯤 접힌 경계가 있으면 상단/시작 쪽의 가려지지 않는 영역을 사용합니다.
  접힘 경계 양쪽에 서로 다른 화면을 배치하는 방식은 아닙니다.
- 휴대폰 가계부는 세로 목록과 스크롤 가능한 입력 폼을 사용합니다.
- `Where`에는 전체 과거 지출에서 최대 8개 장소를 제안합니다. 대소문자와 양끝
  공백을 무시해 중복을 합치고 최근 날짜의 표기를 사용합니다. 앞부분 일치가
  먼저 나오고 부분 일치가 이어집니다. 새 장소도 자유롭게 입력할 수 있습니다.
  터치·방향키·Enter로 선택해도 지출 자체가 자동 저장되지는 않습니다.

## 저장·충돌·오프라인

- 편집 중인 내용은 로컬 복구 초안으로 보관합니다. 서버에는 저장된 파일만
  동기화하며, 자동 동기화는 저장되지 않은 편집이 있으면 기다립니다.
- 같은 파일을 두 기기에서 다르게 수정하거나 수정과 삭제가 겹치면 동기화를
  멈춥니다. 계정 화면에서 파일별로 **이 기기** 또는 **서버** 버전을 선택합니다.
- 교체/삭제되는 로컬 파일은 `.trash/sync/`에 사본을 보관합니다. 복구 초안,
  휴지통, 동기화 상태 파일은 서버로 보내지 않습니다.
- 로그인 세션은 Android Keystore 또는 macOS 로그인 Keychain에 보관합니다.
- 저장소 하나는 하나의 서버/계정에 연결됩니다. 다른 계정으로 같은 로컬
  저장소를 업로드하려 하면 차단합니다. 계정별로 별도 저장소를 사용해야 합니다.
- 파일당 동기화 한도는 25 MiB입니다. 실패하면 로컬 내용을 보존하고 재시도합니다.
- 앱 종료 상태의 백그라운드 동기화와 문장 단위 실시간 공동 편집은 지원하지 않습니다.

## 서버 구성과 검증

`supabase/migrations/`의 SQL을 해당 새 프로젝트에 직접 적용했습니다.
`vault_manifests`는 사용자별 파일 목록과 버전을 보관하고, `vault-blobs`는 비공개
파일 저장소입니다. 파일 내용의 SHA-256 해시로 무결성을 확인합니다.
동기화 RPC는 기대한 서버 버전과 현재 버전이 일치할 때만 저장합니다.

실제 서버에서 다음을 검증했습니다.

- 비로그인 사용자의 목록 조회·동기화 RPC 접근 차단
- 로그인한 사용자의 자기 목록 조회·동기화 허용
- 다른 사용자 목록 조회 차단
- 버전을 무시하는 직접 쓰기 차단 및 오래된 버전의 동기화 거절
- 비공개 Storage 버킷과 사용자별 파일 접근 정책

검증용 사용자 행은 트랜잭션 롤백으로 남기지 않았습니다. SQL Editor로 적용한
마이그레이션은 CLI의 마이그레이션 이력에 자동 기록되지 않으므로 기존 프로젝트에
첫 생성 SQL을 다시 실행하지 마세요. 새 환경에는 파일 순서대로 적용하면 됩니다.

클라이언트에 포함된 publishable key는 공개용이며 `secret`/`service_role` 키를
사용하지 않습니다. 다른 프로젝트로 빌드할 때에는 다음 값을 지정합니다.

```sh
flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

전송은 별도 기기 확인이 필요합니다. PC의 첫 업로드는 앱의 완료 표시와 실제
서버 파일 목록·비공개 저장 파일 존재까지 확인했습니다.
