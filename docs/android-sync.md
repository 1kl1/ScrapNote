# Android · 폴더블 · Scrap 업로드

## 휴대폰의 역할

휴대폰은 Scrap 수집용입니다. 글·사진을 작성하고, 이 휴대폰에서 작성한
Scrap과 전송 상태를 확인합니다. Note·Timeline·Expenses 메뉴와 데이터 로딩은
제공하지 않습니다. 펼친 폴더블에서도 같은 기능을 사용합니다. PC의 전체
작업 공간과 양방향 Vault 동기화는 그대로 유지합니다.

1. 최신 서버를 배포한 뒤 `build/app/outputs/flutter-apk/app-debug.apk`를 설치합니다.
2. 앱 전용 저장소가 자동 생성됩니다. 별도 폴더 권한은 필요하지 않습니다.
3. 구름 아이콘에서 개인 서버 계정으로 로그인합니다.
4. 글·사진을 작성하고 저장합니다. 먼저 기기에 저장한 뒤 자동 업로드합니다.
5. 목록과 하단 상태에서 대기·전송 중·완료·실패를 확인합니다. 하단 재시도
   버튼은 편집 내용을 저장하고 다시 전송합니다. 전송 내역에서 실패 이유와
   충돌을 확인할 수 있습니다.

사진 전송 중에는 현재 사진 번호와 본문·서버 저장 단계를 표시합니다.
오프라인이나 로그인 만료 때에도 기기에 저장한 자료와 작성 중 초안은 남습니다.
앱이 열려 있는 동안 저장·로그인·앱 복귀 시 전송을 시도하고, 1분 간격으로
해당 휴대폰 Scrap의 상태를 다시 확인합니다. 앱 종료 상태의 백그라운드 전송은
포함하지 않습니다. 앱 삭제 시 앱 전용 로컬 파일도 삭제되므로 미전송 자료는
먼저 업로드해야 합니다.

## 수정·삭제·충돌

업로드를 마친 Scrap도 휴대폰에서 수정할 수 있습니다. 삭제 버튼은 확인을 거쳐
기기에서 삭제하고 서버 삭제를 대기열에 넣습니다. 서버 변경은 PC의 다음
동기화 때 반영됩니다. 서버 삭제는 기기 공간만 정리하는 기능이 아닙니다.

PC가 해당 Scrap을 수정·삭제했다면 휴대폰의 다음 전송 확인 때 반영합니다.
저장하지 않은 편집 내용이 있으면 서버 변경 적용을 보류합니다. 양쪽에서
다르게 변경했거나 수정·삭제가 겹쳤다면 전송 내역에서 두 내용을 확인하고
이 기기 또는 서버 버전을 선택합니다. 오래된 충돌 선택은 다시 검증합니다.
교체·삭제된 로컬 원본은 `.trash/capture/`에 보관합니다.

전송 도중 연결이 끊겨도 같은 요청을 재시도합니다. 서버가 이미 처리한 요청은
재적용하지 않으므로 중복 생성과 이후 PC 변경의 덮어쓰기를 방지합니다.
사진은 필요한 첨부만 보내며, 전송 완료 지점을 보관해 재시도·본문 수정 때 이미 올린 사진은 건너뜁니다. 파일별 SHA-256과 25 MiB 한도를 확인합니다.
새 사진은 기존 이미지 최적화와 GPS 메타데이터 저장 방식을 사용합니다.
서버의 사진 저장소는 기존 Zipline을 재사용합니다.

## 기존 모바일 저장소 이전

새 수집 저장소는 앱 지원 폴더의 `capture-v1/`입니다. 기존 `vault/` 또는
`vault-oracle/`는 원본 그대로 보존합니다. 이전 전송 기록과 비교해 미전송
작성·수정·삭제를 가져오고, 작성 중 Scrap 초안이 참조하는 저장 파일도 보존합니다.
PC에서 내려받았고 수정하지 않은 자료는 새 작성 목록에 넣지 않습니다.
기존 Note·지출 파일과 Note 복구 초안은 원래 위치에 남습니다.

이전 전송 기록이 손상되었다면 출처를 확인할 수 없는 파일의 자동 재업로드를
보류하고 전송 내역에 안내를 표시합니다. 저장소는 서버·계정에 연결되며,
다른 계정으로 바꾸어 기존 대기 자료를 업로드하는 것은 차단합니다.

## 서버와 PC 호환성

서버 주소는 `https://scrapnote.134.185.114.149.sslip.io`입니다.
새 앱보다 서버를 먼저 업데이트해야 합니다. 초기화 시 `capture_receipts`
테이블을 추가하며 기존 Vault와 PC 클라이언트 프로토콜은 유지합니다.

- `POST /v1/capture/status`: 요청한 Scrap 경로만 최대 100개씩 조회합니다.
- `POST /v1/capture`: Scrap 한 건과 첨부 경로만 병합합니다. 기존 버전이
  일치해야 반영하며, 다른 Note·지출·Scrap과 공유 첨부는 보존합니다.
- 전송마다 영구 식별자를 저장합니다. 서버 영수증과 휴대폰의 원자적 상태
  파일·본문 사본을 사용해 응답 유실 이후에도 안전하게 재시도합니다.
- PC의 전체 목록 교체와 모바일 변경은 같은 PostgreSQL 행 잠금을 사용합니다.
  PC의 오래된 전체 목록은 버전 불일치로 거절되어 새 모바일 자료를 지우지 않습니다.

기존 계정 화면의 `0 / 0 / 0 / 0`은 서버 전체 개수가 아니라 기기 파일 수였습니다.
새 모바일 화면에서는 휴대폰의 작성·전송 내역만 표시합니다. 전체 서버 다운로드는
실행하지 않으므로 과거 사진 수 때문에 첫 로그인 후 다운로드를 기다리지 않습니다.

## 개발 검증

```sh
flutter analyze
flutter test
flutter test --dart-define=CAPTURE_MOBILE=true test/app/mobile_capture_test.dart
flutter build apk --debug
cd server
TEST_DATABASE_URL=postgresql://... npm test
```

화면 검증은 320·375·414·768px, 키보드와 삭제 확인을 포함합니다. 동기화 검증은
응답 유실, 부분 실패, 재실행, 계정 변경, PC 수정·삭제 충돌과 실제 PostgreSQL의
동시 커밋·롤백을 포함합니다. 물리 기기에서 운영 계정의 전송 확인은 별도입니다.
